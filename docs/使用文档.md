# 绳网论坛 使用文档

本项目是一个可部署到 Netlify 的论坛网站，包含**前台用户论坛**与**后台管理端**，前后端分离。本文档面向部署与日常使用。

---

## 一、项目简介

| 项目 | 说明 |
|------|------|
| 前端 | Nuxt 4（Vue 3）+ Pinia + TanStack Vue Query，UI 复刻《绝区零》绳网风格 |
| 后端 | Netlify Functions（v2 语法），单入口 `netlify/functions/api.ts` 路由 `/api/*` |
| 存储 | **Netlify Blobs**：结构化数据（JSON 文档）存 `data` store，图片字节存 `uploads` store |
| 图片 | 上传时服务端用 sharp 自动转 WebP、最长边 2048px、剥 EXIF |

### 功能范围

- **前台**：首页信息流（推荐/关注/收藏）、版块 Tab、搜索、发帖/草稿/匿名发布、帖子详情（Markdown + 楼中楼评论 + 点赞/收藏/三连/举报）、注册登录、个人主页。
- **后台（`/admin`）**：数据概览、用户管理、帖子管理、评论管理、版块管理、站点设置。仅管理员可访问。

## 二、本地开发

### 1. 环境要求

- Node.js ≥ 20.18
- npm
- Netlify CLI（本地联调前后端必需）

```bash
# 安装 Netlify CLI（一次性）
npm install -g netlify-cli
```

### 2. 安装依赖

```bash
npm install --legacy-peer-deps
```

> 模板部分依赖存在 peer 冲突，需加 `--legacy-peer-deps`。

### 3. 配置环境变量

```bash
cp .env.example .env
```

修改 `.env` 中的关键项（尤其是 `JWT_SECRET`）：

| 变量 | 说明 | 默认 |
|------|------|------|
| `NUXT_PUBLIC_API_BASE_URL` | 后端地址，同源部署/`netlify dev` 时留空 | 空 |
| `JWT_SECRET` | JWT 签发密钥，**生产必须修改** | dev 占位 |
| `ADMIN_INITIAL_PASSWORD` | 初始化管理员密码 | admin123456 |

### 4. 启动

```bash
netlify dev
```

- 打开 `http://localhost:8888`（默认端口）。
- `netlify dev` 会同时启动 Nuxt 前端与 Netlify Functions，`/api/*` 同源可用；**不需要任何数据库**。
- 首次请求 `/api` 时自动写入种子数据（默认版块 + 管理员账号）。

> 如果只用 `npm run dev`，页面能打开但 `/api` 请求无响应，请改用 `netlify dev`。

## 三、部署到 Netlify

1. 将代码推送到 GitHub 仓库。
2. Netlify → **Add new site → Import an existing project** → 选择该仓库。
3. 构建配置已写在 `netlify.toml`，无需手动填写：
   - Build command：`npm run generate`
   - Publish directory：`.output/public`
   - Functions directory：`netlify/functions`
4. 在 **Site settings → Environment variables** 中添加：
   - `JWT_SECRET`（务必设置随机长字符串）
   - `ADMIN_INITIAL_PASSWORD`
5. 首次部署完成即自动写入种子数据；用管理员账号登录即可访问 `/admin`。

> 后续每次 `git push` 自动重新部署。Blobs 数据随站点持久化，重新部署不会清空。

### 米游社扫码登录/绑定（可选）

后端已对接 `passport-api.mihoyo.com` 扫码流程，但依赖米游社官方 Web 客户端下发的**私有参数**（社区逆向维护，无官方文档）。这些参数需自行从米游社官网抓包获取：

1. 浏览器打开 `https://user.mihoyo.com` 登录页，按 `F12` 打开开发者工具 → **Network** 面板。
2. 触发一次登录（或点击"扫码登录"），过滤 `passport-api.mihoyo.com`，打开 **createQRLogin** 请求（POST `/account/ma-cn-passport/web/createQRLogin`）。
3. 依次复制以下**请求头**到环境变量：

| 环境变量 | 取自请求头 |
|----------|------------|
| `MIHOYO_APP_ID` | `x-rpc-app_id` |
| `MIHOYO_DEVICE_ID` | `x-rpc-device_id`（可选） |
| `MIHOYO_DEVICE_FP` | `x-rpc-device_fp`（可选） |

4. 本地放入 `.env`；线上在 **Netlify → Site settings → Environment variables** 添加同名变量（`MIHOYO_APP_ID` 必填）。
5. 配置后访问 `/account` → 米哈游账号，即可渲染二维码扫码绑定/登录；未配置时接口返回 501。

> 注意：这些参数随米游社版本更新可能失效，需要定期重新抓包核对；逆向调用非官方接口存在账号风控风险，请自行评估。

### Fairy AI 对话（智谱 GLM）

敲敲「通话」Tab 内置 Fairy（自称「偷偷潜伏在暗处的超级人工智能」）对话，回复由智谱 GLM 生成。

- **默认可直接使用**：后端已内置智谱 API 密钥（`GLM_API_KEY`），无需额外配置即可对话。
- 如需更换密钥：在 Netlify 站点后台 **Site settings → Environment variables** 添加 `GLM_API_KEY`（scope 含 Functions），或本地 `.env` 添加同名变量；环境变量优先于内置密钥。
- 模型默认 `glm-4-flash`，可用 `GLM_MODEL` 覆盖。

## 四、后台管理使用说明

访问 `https://<你的站点域名>/admin`，用管理员账号登录（密钥登录或米游社扫码）。

### 登录方式
- **米游社扫码登录**：首次登录唯一入口，扫码后自动创建账号并生成 16 位密钥（仅显示一次，需妥善保管）。
- **密钥登录**：使用米游社登录时生成的密钥直接登录，无需扫码。

### 数据概览
顶部卡片展示注册用户、帖子总数、评论总数、总浏览量、今日新帖、今日评论、待审核、版块数；下方为最新注册用户与最新帖子。

### 用户管理
- 支持按用户名/昵称/UID 搜索。
- 可调整角色：用户 / 版主 / 管理员。
- 可禁用 / 解禁账号（禁用后无法登录）。

### 帖子管理
- 按标题/正文搜索，按状态筛选（已发布 / 待审核 / 草稿 / 已删除）。
- 操作：置顶 / 取消置顶、下架 / 恢复显示、发布、删除。

### 评论管理
- 按内容搜索，可删除违规评论。

### 版块管理
- 新增/编辑/删除版块，可调整排序与隐藏。

### 站点设置
- 站点名称、公告、导航开关、等级体系开关、AI 对话开关等。

> 管理员账号使用米游社扫码登录后会自动生成密钥，用密钥可直接登录后台。忘记密钥可重新扫码获取。

## 五、前台使用说明

### 注册 / 登录
- **首次登录**：米游社扫码登录，扫码后自动创建绳网账号，并生成 16 位密钥（仅显示一次，需妥善保管）。
- **后续登录**：使用密钥登录（输入米游社登录时生成的密钥），或再次扫码。
- 密钥丢失可重新扫码登录获取新密钥。

### 发帖（发布帖子）
- `/create` 进入编辑器：标题 + 正文（Markdown）+ 封面图片 + 分类。
- 图片上传后服务端**自动转 WebP**：原始 ≤10MB、最长边压缩到 2048px、质量 80、剥离 EXIF/GPS。
- 支持草稿箱（自动保存）与匿名发布；发布后可在首页与个人主页看到。

### 帖子详情
- 正文用 Markdown 渲染（DOMPurify 过滤 XSS）。
- 支持楼中楼评论、点赞、收藏、一键三连、举报。

### 个人主页
- `/profile/:id` 展示名片、统计（帖子/评论/浏览/点赞）与帖子列表。
- 本人可改昵称、简介、头像。

## 六、数据存储结构（Netlify Blobs）

所有数据都在两个 store 中：

### `data` store（结构化 JSON）

| 前缀 / key | 内容 |
|-----------|------|
| `users/<id>.json` | 用户（含角色/状态/统计/关注数/密钥） |
| `users/by-key/<密钥>.json` | 登录密钥 → 用户索引（登录用） |
| `categories/<id>.json` | 版块 |
| `posts/<id>.json` | 帖子（含作者与分类冗余字段） |
| `comments/<postId>/<id>.json` | 评论（楼中楼用 `parent_id`） |
| `likes/<uid>/article\|comment/<target>.json` | 点赞记录（存在即已赞） |
| `favorites/<uid>/<post>.json` | 收藏记录 |
| `follows/<uid>/<target>.json` | 关注记录 |
| `user_blocks/<uid>/<target>.json` | 拉黑记录 |
| `reports/<uid>/<type>/<target>.json` | 举报记录 |
| `read_records/<uid>/<post>.json` | 已读记录 |
| `uploads/<hash>.json`、`uploads/by-document/<id>.json` | 上传文件元数据与按 documentId 索引 |
| `settings.json` | 站点设置 |
| `stats.json` | 全局计数 |
| `_indexes/feed.json` | 信息流索引（最新已发布帖子，供列表/搜索/分页） |
| `_indexes/drafts/<uid>.json` 等 | 草稿 / 用户评论 / 评论查找索引 |

### `uploads` store（图片字节）

- key：`<contentHash>.webp`，URL 形如 `/api/uploads/<contentHash>.webp`。
- 同一图片内容重复上传会自动复用（内容级去重）。

### 注意事项

- **无事务**：计数采用"读-改-写"，极端并发下可能出现轻微计数偏差；中小流量可忽略。
- **无查询**：`list()` 只返回 key，需要扫描前缀过滤（版块/作者/后台列表）。数据量很大时建议改用关系数据库或加缓存。
- **迁移**：如需换存储，可直接把 `data` store 的 JSON 文档导出到新后端。

## 七、常见问题

| 问题 | 解决 |
|------|------|
| 本地 `/api` 请求失败 | 使用 `netlify dev`，不要用 `npm run dev` |
| 登录/注册报错 | 检查 `.env` 的 `JWT_SECRET` 与 `ADMIN_INITIAL_*`；首次访问需先触发 `/api` 写入种子 |
| 上传图片失败 | 确认原始文件 ≤10MB 且为 jpeg/png/webp；Blobs 权限默认跟随站点 |
| 管理员进不去 `/admin` | 确认登录账号角色为 `admin`；前端 Tab 只在 `user.isAdmin` 时显示 |
| 函数首次访问慢 | 冷启动属正常现象，可忽略或改用 Edge Functions 处理高频读接口 |
| 依赖安装报 peer 冲突 | `npm install --legacy-peer-deps` |
| Netlify 构建失败 | 检查环境变量是否在 Netlify 站点内配置（.env 不提交） |
