# 将项目链接到 GitHub 操作文档

本文档介绍如何将本项目上传并关联到 GitHub，采用「网页创建仓库 + 命令行推送」的方式，无需安装额外软件。以下方法对**公开仓库**和**私有仓库**都适用，差别仅在第 2.3 步选择可见性。

---

## 一、准备工作

1. 确认电脑已安装 Git。
   - 打开 PowerShell 或 CMD，输入：`git --version`
   - 能显示版本号（如 `git version 2.55.0.windows.3`）即可。
2. 注册并登录一个 GitHub 账号：https://github.com
3. 配置 Git 用户信息（首次使用时需要，之后不用重复）：
   ```powershell
   git config --global user.name "你的GitHub用户名"
   git config --global user.email "你的GitHub邮箱"
   ```

---

## 二、在 GitHub 网页上创建仓库

1. 浏览器登录 GitHub 后，点击右上角 `+` → `New repository`。
2. 填写仓库信息：
   - **Repository name**：仓库名，建议与项目文件夹同名，例如 `04-inter-knot`。
   - **Description**：可选，仓库描述（如"Epic 3D Starfield Nebula 动画项目"）。
   - **Visibility**：选择可见性：
     - **Public**（公开）：任何人可见、可访问。
     - **Private**（私有）：仅自己和被邀请的协作者可见。
   - **Initialize this repository with...**：**不要**勾选 README、.gitignore、License。
     > 原因：本地已经有文件，勾选了会多出文件导致首次推送冲突。
3. 点击绿色按钮 **Create repository**。
4. 创建成功后，页面会显示一个仓库地址，记录下它（形如 `https://github.com/你的用户名/04-inter-knot.git`），后续第 3.4 步要用。

---

## 三、本地初始化 Git 并推送

在项目文件夹内打开 PowerShell，依次执行：

```powershell
# 1. 进入项目目录（如已在该目录可跳过）
cd E:\项目开发\04-inter-knot

# 2. 初始化本地 Git 仓库
git init

# 3. 将项目所有文件加入暂存区，并完成首次提交
git add .
git commit -m "Initial commit"

# 4. 将主分支命名为 main（与 GitHub 默认分支一致）
git branch -M main

# 5. 关联远程仓库（将下面地址替换成第二步记下的地址）
git remote add origin https://github.com/你的用户名/04-inter-knot.git

# 6. 推送到 GitHub（首次推送会弹出登录窗口，输入 GitHub 账号密码或使用浏览器授权）
git push -u origin main
```

推送完成后，刷新 GitHub 仓库页面，即可看到项目文件。

---

## 四、后续日常更新项目

每次修改完文件后，只需三步即可同步到 GitHub：

```powershell
git add .
git commit -m "本次修改的说明"
git push
```

---

## 五、常见问题

### 1. 推送时报错 "remote origin already exists"
说明之前已关联过远程仓库，先删除再重新添加：

```powershell
git remote remove origin
git remote add origin https://github.com/你的用户名/04-inter-knot.git
```

### 2. 推送时要求输入用户名密码 / 登录失败
- GitHub 已不再支持纯密码推送，请使用**个人访问令牌（Personal Access Token）**。
- 生成方法：GitHub 头像 → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token，勾选 `repo` 权限，复制生成的令牌。
- 推送时，用户名填 GitHub 用户名，密码处粘贴该令牌。
- 使用 HTTPS 首次推送后，Windows 凭据管理器会记住凭据，后续无需重复输入。

### 3. 想排除不需要上传的文件（如临时文件、密钥）
在项目根目录新建 `.gitignore` 文件，把要忽略的文件名或目录写进去，例如：

```
node_modules/
*.log
.env
```

### 4. 已推送的内容里不小心包含了敏感信息
1. 立即在 GitHub 上删除或使其失效（如吊销令牌）。
2. 修改本地内容并重新提交推送。
3. 密码、密钥等敏感信息原则上**不应提交**到任何仓库。

---

## 六、仓库可见性切换

已创建的仓库可以随时在网页上切换公开/私有：
仓库页面 → `Settings` → 左侧 `General` → 底部 `Danger Zone` → **Change repository visibility** → 选择 Public 或 Private。
